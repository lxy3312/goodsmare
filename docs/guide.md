## 第一次使用

1. **新建关注**：一个关注就是一个搜索词。
   - 关键词用日文最准。表单里有常用谷子词对照，比如 吧唧 → 缶バッジ、立牌 → アクリルスタンド，点一下就填进去。
    - 勾选在哪几个网站找，填价格区间（日元）。关注优先级可选重点、普通、低频；只将最想抢的几个设为重点，同站请求预算会优先分给它们。
   - 煤炉和雅虎闲置的搜索会匹配商品描述，结果比较杂，建议填「标题必须包含」。同一个东西有几种写法的，用竖线隔开，有一个就行：`フィッシュマンズ|fishmans`。不想要的，比如「まとめ売り」，填进「标题不能包含」。
   - 全角半角、大小写会自动统一：`ｶﾝﾊﾞｯｼﾞ` 等于 `カンバッジ`。
2. **先预览**：点「先搜一下看看」，直接看搜出来的东西，灰掉的是会被你的条件过滤掉的。建好以后，在「关注」页点网站名，可以直接去那个网站看同一个搜索。
3. **第一次扫描只记不推**：新关注第一次扫描只记下现有商品，之后新上架的才推送，不然一加就刷屏上百条。改了关键词或价格区间也会重新记一遍。
4. **配推送**：在「推送」里加一个渠道，点「发一条测试」。测试会用最近抓到的一件真实商品；还没抓到过的话，就用第一个关注现搜一件。所以测试消息里的封面和链接，和正式推送一样。

## 推送渠道怎么选

| 渠道 | 适合 | 要填 |
|---|---|---|
| WxPusher | 手机 App 收提醒，支持安卓、iPhone、鸿蒙；个人使用推荐极简推送 | [扫码获取 SPT](https://wxpusher.zjiecode.com/docs/spt.html)，只填「推送令牌」即可；也支持应用令牌，见下面说明 |
| 虾推啥 | 微信收提醒，不另装 App | [关注公众号获取 Token](https://xtuis.cn/xtuisstart.html)。免费每天 300 条、每分钟 30 条，正文和链接需点开消息详情查看 |
| PushMe | 安卓手机，免注册；也能使用自建服务器 | [安装 App 并获取 Push Key](https://push.i-i.me/docs/guide)；按教程允许后台运行和通知。自建时再填服务器地址 |
| 爱语飞飞 IYUU | 微信收提醒、通知数量不多 | [微信扫码获取 IYUU 令牌](https://iyuu.cn/)，按 IP 每小时限 20 条 |
| Discord | 平时已经用 Discord，在自己的频道看带图商品卡片 | [频道 Webhook 地址](https://support.discord.com/hc/en-us/articles/228383668-Intro-to-Webhooks)，可使用普通文字频道 |
| Pushover | 安卓、iPhone、电脑都想收专门的通知 | [注册应用](https://pushover.net/)取得 API Token，再填首页的 User Key（或 Group Key）。设备名和提示音可留空；客户端试用结束后需按平台买断，价格见[官网](https://pushover.net/pricing) |
| Server酱 | 推到微信，最省事 | SendKey（[sct.ftqq.com](https://sct.ftqq.com)）。免费版每天 5 条，几秒内查到的合成一条发 |
| PushPlus | 推到微信，免费额度更多 | Token（[pushplus.plus](https://www.pushplus.plus)） |
| 企业微信群机器人 | 一次推送一条消息，一件一行「价格 标题」，点开就去买 | 群机器人的 Webhook 地址 |
| 钉钉 / 飞书群机器人 | 用钉钉、飞书的 | Webhook。钉钉的安全设置选「自定义关键词」就填 `goodsmare`，选「加签」就把密钥也填上 |
| Bark | iPhone，每件单独一条，点开直达商品页 | Bark App 里的设备 Key |
| ntfy | 安卓 / 自建 | 主题名 |
| Telegram | 用 TG 的 | Bot Token 和 Chat ID |
| 邮件 | 不急的 | SMTP 服务器和授权码（QQ、163 邮箱要用授权码，不是登录密码） |
| Webhook | 自己接 QQ 机器人等 | 地址。每次把命中的商品以 JSON POST 过去 |

在「推送 → 添加推送」里选择渠道、填好凭据，点「发一条测试」后保存。上面所有渠道都有独立的配置入口；飞书、邮件、Bark 等原有渠道仍可直接使用。各服务的免费额度和收费规则以官网为准。

WxPusher 有两种填法：只给自己发时，填一个 `SPT_` 开头的令牌，不用填 UID 或主题；要给多个接收人发，可以填多个 SPT（逗号隔开，最多 10 个）。已经有应用时，填 `AT_` 开头的应用令牌，并至少填写「接收 UID」或「主题 ID」中的一项，多个值用逗号隔开。绑定和接收设置见[官方文档](https://wxpusher.zjiecode.com/docs/)。

六个新增渠道会把同一批商品合并发送，内容太长时自动按整件商品拆分，链接仍对应正确的商品。Discord 每条最多放 10 张商品卡片，遇到短暂限流会按照接口返回的等待时间重试。Pushover 每条正文最多 1024 字，会自动拆分。只有填写渠道并启用后才会收到正式推送。

每件商品都带价格和打开商品的链接，各渠道能显示图片的程度不一样：

- **Server酱、PushPlus**：走的是微信的模板消息，微信聊天里那张卡片本身放不了图片，**点开卡片**才看得到封面和商品链接。
- **想在通知里直接看到图**：iPhone 用 Bark；企业微信在推送渠道里打开「用图文卡片（带小图）」，每件一张带小图的卡片。不开时一件一行文字，最短。
- **点开直接去任意门买**：在「推送」页的「点开商品去哪」选「任意门」。煤炉、雅虎拍卖、雅虎闲置、乐天、骏河屋的商品点开就是任意门的商品页，不用再复制链接、打开 App、粘贴搜索；第一次要在手机浏览器里登录任意门。Mandarake、animate、闲鱼任意门没有，还是打开原网页。日淘市集没有公开的商品链接，做不到。
- **飞书**：群机器人的消息放不了外链图片，只有文字和链接。
- **WxPusher**：消息正文是一件一张的大图卡片，带价格和「去任意门」「复制原链接」「原商品页」按钮。复制用的是 WxPusher 官方支持的原生按钮，不用先开手机访问，也不用手机连回这台电脑。任意门不支持的来源只显示复制和原商品页。
- **WxPusher 点通知直达任意门**：先在 goodsmare 的「推送 → 点开商品去哪」选「任意门」，再在手机 WxPusher 的「我的 → 通用 → 通知点击设置」里选「原文链接」（找不到时先更新 App）。通知会打开这批第一件商品的任意门商品页；查看整批商品和复制链接时，在 WxPusher 消息列表点开消息正文即可。这个手机设置发送方无法代为开启，详见[官方说明](https://github.com/wxpusher/wxpusher-docs/blob/master/docs/url-scheme.md)。
- **PushMe**：消息正文显示小图、价格和可点击的商品链接。
- **Discord**：每件商品一张带小图、价格和链接的卡片。
- **虾推啥、IYUU**：消息详情里显示商品列表和链接。**Pushover**：发送文字、价格和链接，不上传图片附件。

开着网页时，还可以在「推送」里打开浏览器通知和提示音。

## 自定义推送内容：消息积木

打开「推送 → 消息积木」，先选一个预设：**大图购物、精简抢购、完整信息、纯文字**。再点击方块增减模块，拖动下方已选积木调整顺序；手机上用左右箭头排序。点「保存布局」后，后续推送生效。

可以组合 24 个模块：商品配图、标题、上新/降价状态、编号、价格、人民币估算、降价幅度、来源、关注名、关键词、成色/运费、上架时间、发现时间、去任意门、打开原页、复制原链接、复制任意门链接、查看原图、同站搜索、推送页、编辑关注、两段自定义文字和分隔线。没有对应数据时自动隐藏，例如闲鱼不显示日元换算和任意门按钮，普通上新不显示降价幅度。

顶部选择「全部渠道」可以统一配置，也可以选择某一个渠道独立设置。某个渠道点「改为跟随全局」再保存，就会恢复继承。关闭「使用自定义布局」并保存，会使用该渠道原有格式。初次升级保留原有格式，选择任何预设或方块即可开始自定义。定时刷新和切换渠道都会保留未保存的草稿。

支持小/中/大图、舒展/紧凑排版、商品标题长度、每条汇总最多几件和整条通知的点击目标。件数设为 0 时按渠道容量自动拆分，设置上限也不会丢弃其余商品。标题模板和两段自定义文字可以插入 `{标题}`、`{价格}`、`{人民币}`、`{来源}`、`{关注}`、`{关键词}`、`{状态}`、`{数量}`、`{原链接}`、`{任意门链接}`、`{商品编号}`；点击变量按钮会插入最近编辑的文本框。

右侧预览使用实际发送时的内容渲染，可切换最近商品、日站、降价和闲鱼示例，预览不会搜索、发送消息或生成推送页。外观以接收客户端为准：WxPusher 提供原生复制按钮；其他渠道一般显示可长按复制的链接，Bark 则可以长按系统通知复制。飞书、虾推啥、Pushover 的当前接入将配图显示为链接；Discord、系统通知的标题/附件位置由客户端固定。渠道说明会随预览切换。

「打开推送页」「编辑这个关注」需要先配置手机访问；它们不会替你开启局域网。整条通知的点击目标只作用于提供通知点击入口的渠道，正文操作模块分别打开各自链接。WxPusher 还需在手机端将「通知点击设置」设为「原文链接」。

布局保存在 `config.json` 的 `message` 字段，渠道独立布局在对应渠道的 `message` 字段；缺少该字段表示继承全局。`message: null` 的全局配置沿用原有格式，迁移工具也会带上布局设置。

## 推送页和手机访问

推送页要先在「设置 → 手机访问」里打开，手机连得上电脑才有。打开以后，每轮推送会多生成一个推送页：Bark、ntfy 点开推送直接到这一页，企业微信和其他渠道在消息开头放一个推送页的链接。没打开时，推送里的链接直接去商品所在的网站。推送页上每件商品有大图、日元价格和大概的人民币、降了多少、成色和运费（煤炉、雅虎拍卖有）、上架时间、关注名，还有「打开原商品页」和「复制链接」两个按钮，复制下来可以贴到代购网站。推送页保留 30 天，看它不用口令，链接里那串随机字符就是钥匙，别转给别人。

页面在你的电脑上，所以手机得能连到电脑：

1. 在电脑上打开 goodsmare，进「设置 → 手机访问」，打开「让手机也能打开这个网页」。第一次打开时 Windows 会弹防火墙提示，点「允许访问」。
2. 用手机扫页面上的二维码。最好用收推送的那个 App 扫，比如企业微信的「扫一扫」，口令会记在那个 App 里。
3. 点「推送」里的「发一条测试」，在手机上点开，应该就是推送页了。

之后在手机上也能看上新、改关注、加关注，界面和电脑上一样。推送页上的「管理关注」和每件商品旁边的「改条件」也会直接跳过去。企业微信、钉钉、飞书的群机器人都只能发消息，收不到你回的话，所以想在手机上改东西只能靠打开这个网页。

局域网地址只在同一个 Wi-Fi 下有用，出了家门手机就打不开推送页了。想在外面也能用，有几种办法：

- **Tailscale**：电脑和手机都装上、登录同一个账号，「手机用哪个地址打开」里会多出一个「Tailscale 等」的地址，选它就行。不用把电脑暴露到公网，推荐。
- **内网穿透**（frp、cpolar、花生壳之类）：把本机的 8787 端口映射出去，把得到的地址填进「自己填」。这样任何人知道地址都能连上来，全靠口令挡着，口令别外传。
- **放到 NAS 或服务器上跑**，见下一节。

在外面打不开又暂时不想折腾的话，把「推送点开后」改成「直接去原商品页」，推送就和以前一样直接打开商品所在的网站。

手机打不开时按这个顺序查：手机和电脑是不是连的同一个 Wi-Fi（手机别用流量）；Windows 防火墙有没有放行 Python（控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙，把 Python 的「专用」「公用」都勾上）；Windows 是不是把这个 Wi-Fi 当成了「公用网络」（设置 → 网络和 Internet 里改成「专用」）；路由器有没有开「AP 隔离」，手机是不是连到了访客网络；列了好几个地址的话，换一个试试。

## 闲鱼

闲鱼不登录搜不了，要先登录一次：

1. 进「设置 → 闲鱼账号」，点「扫码登录」，用闲鱼 App 的扫一扫扫页面上的二维码，再在手机上确认。
2. 登录好以后程序会马上试搜一次，告诉你能不能用。然后在关注里勾上「闲鱼」，或者点「给所有关注加上闲鱼」。

几点说明：

- 登录信息（cookie）只存在这台电脑的 data 文件夹里，只拿来搜闲鱼。从旧版迁移时会一起带过来。
- 用的是你自己的账号。程序为闲鱼设置了同一个关注至少隔 5 分钟、两次查询至少隔 5 秒的保护值，并非平台公布的安全额度。登录失效时暂停该站，重新登录后恢复；验证或限流会进入冷却。
- 闲鱼的价格是人民币，网页和推送里直接写「380元」。关注里的价格区间还是按日元填，比的时候把闲鱼的价格按汇率换成日元。
- 闲鱼上中文标题多，日文关键词常常搜不到东西，可以另建一个中文关键词的关注，只勾闲鱼。
- 闲鱼是国内网站，请求不走代理。
- 扫码登录不了的话，可以从电脑浏览器复制登录信息：在浏览器里登录 goofish.com，按 F12 打开开发者工具，切到「网络」，刷新页面，点一个 goofish.com 的请求，把请求标头里 cookie 的值整段复制，贴到「扫码登录不了？」下面的框里。
- 登录过期了，「关注」页顶上会提示，重新扫一次码就行。

## 命令行

```bash
python -m goodsmare                         # 启动（后台扫描 + 网页）
python -m goodsmare --port 8788             # 换端口
python -m goodsmare once                    # 只扫一轮就退出，适合定时任务
python -m goodsmare search 煤炉 初音ミク     # 试搜一个网站，看解析得对不对
python -m goodsmare search 骏河屋 初音ミク --dump dump/   # 顺便把原始页面存下来
python -m goodsmare add 初音ミク フィギュア --max 8000 --must フィギュア --exclude まとめ
python -m goodsmare list                    # 列出关注和每个网站的最近状态
python -m goodsmare rm <ID>
python -m goodsmare test-notify             # 给所有推送渠道发测试
python -m goodsmare migrate 旧文件夹         # 看看旧版的数据会怎么并进来；加 --apply 真的合并
```

网站名可以写中文：煤炉、雅虎、雅虎闲置、乐天、骏河屋、mandarake、animate、闲鱼。

## 放在 NAS / 服务器上长期运行

```bash
python3 -m goodsmare --host 0.0.0.0 --no-browser
```

对局域网开放时程序会自动生成一个口令（存在 `data/config.json` 的 `web.token`），启动时把带口令的地址打印出来，用它打开一次，浏览器就记住了。想换口令就改这个字段再重启。推送页要用的地址在网页的「设置 → 手机访问」里选，服务器有域名的话填进「自己填」。

也可以不开网页，只用 `once` 配合定时任务：

```cron
*/5 * * * * cd /path/to/goodsmare && python3 -m goodsmare once >> goodsmare.log 2>&1
```

## 设置说明

- **基础检查间隔**：默认 60 秒，最少 10 秒。同站关注按重点、普通、低频分配检查机会，权重为 2、1、0.5；总查询预算不会因为设置优先级而增加，网站最短周期仍然有效。关注数、网络耗时和冷却都会影响实际周期，顶部仅显示调度估算。
- **同站请求间隔**：同一个网站两次查询之间至少等几秒，默认 3 秒；随机等待只会增加，不会缩短这个值。骏河屋、Mandarake、闲鱼还有程序设定的下限。扫描、预览和测试搜索共用间隔与冷却。错误后依次等待 60、120、300、600、900 秒；如果响应的 `Retry-After` 要求更久，则遵守更长的等待。手动扫描和保存关注不清除冷却，重启后也保留剩余时间。
- **推送速度**：默认「全部即时」，发现后不再等待合并窗口。「重点即时」只立即发送重点关注，其余商品合并；「合并发送」等待 3 秒安静期，持续有新商品时最多等 12 秒。即时模式会增加通知条数，不增加购物网站查询次数；额度较少的渠道可选择合并。
- **渠道独立发送**：每个渠道有自己的发送队列，一个渠道变慢不会拖住其他渠道的下一批消息。同一渠道保持顺序。失败写入日志；内存队列不是持久发件箱，强制结束进程会丢失尚未发出的消息，正常退出会等待队列完成。
- **耗时看板**：设置页显示本次运行最近 100 次查询与成功推送的中位耗时，以及待发批次、等待合并的商品数和网站冷却状态。「发现 → 渠道受理」包括程序排队和发送耗时，不代表手机实际显示通知的时间。
- **连接复用**：默认启用 HTTP/HTTPS 长连接，完整读取响应后归还连接，最多保留 32 条空闲连接，空闲 30 秒即过期。代理地址、目标网站和 Cookie 会话隔离；切换设置会丢弃旧连接。HTTPS 始终校验证书。可关闭复用进行对比。
- **按网站分流**：在「各网站线路与耗时」展开每个网站，选择跟随全局、直连或专用 HTTP 代理。日本购物网站默认沿用原线路，闲鱼固定直连；WxPusher 等已识别的国内 HTTP 推送默认直连，海外推送沿用全局，可分别修改。自定义 Webhook 和 SMTP 不属于这两组 HTTP 推送分流。
- **超时与重试**：连接阶段默认 8 秒、响应阶段默认 20 秒；单次调用若指定更短超时，以更短值为准。普通 POST 默认不自动重发，避免已经发送成功但响应丢失时重复通知；只读的煤炉搜索 POST 明确允许一次重试。验证码、限流和 `Retry-After` 不会靠立即重试或切换 IP 绕过。
- **线路统计**：记录最近 100 次完成的请求，显示总耗时、连接、等响应、下载的中位数与复用率；重定向场景的分阶段数据对应最后一跳，总耗时包含整个调用及其重试。更换代理节点后可点击「重新连接当前线路」，清空连接和统计，网站冷却不会被重置。
- **代理**：留空时跟着系统代理走。Clash 之类的软件打开「系统代理」就行，程序每隔几秒重新看一次系统设置，开关随时拨都能跟上，不用重启。也可以直接填，比如 Clash 的 `http://127.0.0.1:7890`，填了就一直走它。只支持 HTTP 代理，日本节点更稳。煤炉、雅虎拍卖、乐天 Rakuma 在国内直连连不上，要走代理；闲鱼不走代理。
- **汇率**：默认自动获取（每 12 小时一次），拿不到就用你填的值。

所有数据都在 `data` 文件夹里：

- `config.json`：设置、关注、推送渠道。网页里改和直接改文件都行，每一轮扫描都会重新读取，不用重启。
- `goodsmare.db`：SQLite 数据库，记着见过的商品、推送记录、各网站的扫描状态和最近 30 天的推送页。

## 从旧版迁移

换新版本，或者从改名前的 ritao 换过来时，旧版的关注、推送渠道、上新记录和见过的商品都能并进来，两边的东西都留着：

1. 打开新版的网页，进「设置 → 从旧版迁移」，填旧版的文件夹（程序文件夹或者它的 data 文件夹都行），点「先看看」。
2. 看一下会怎么合并：哪个关注和现在的是同一个，会并进来多少条记录。没问题就点「合并」。
3. 把旧版关掉，不然两边会各推一遍。

几点说明：

- 旧文件夹里的文件不会被改。合并前，现在的数据会整份备份到 data 里的「迁移前备份-时间」文件夹，想反悔就把里面的两个文件拷回 data。
- 别自己只拷旧版的 .db 文件：最近几天的数据常常还在旁边的 .db-wal 文件里没写回去，只拷 .db 就丢了。用迁移功能不用管这些，它连 WAL 一起读。
- 两边关键词一样的关注认成同一个，记录并到现在这个下面；配置一模一样的推送渠道只留一个。扫描间隔、代理这些设置保留现在的，只有新版还什么都没配过时才沿用旧版的。
- 旧版骏河屋的价格是按有问题的解析记的，这部分「见过的商品」不并进来，免得报出假降价；推送记录照样并进来。
- 做两次也不会重复。

命令行也能做：`python -m goodsmare migrate 旧文件夹` 先看看，加上 `--apply` 真的合并。用命令行合并前要先把 goodsmare 关掉。

## 工作原理

```
你的关注（关键词 + 价格、必含词、排除词）
        ↓  每个网站各自不停地轮着查
各个网站同时去搜，只看「按上架时间排序」的第一页
        ↓
把各站的结果整理成同一种格式：编号、标题、价格、封面、链接
        ↓
和数据库里「见过的」对比：没见过 = 上新；见过但比上次便宜一成以上 = 降价
        ↓
过滤：价格不对、缺必含词、有排除词、已售的都扔掉
        ↓
合成推送发出，同时显示在网页的「上新」里
```

- **怎么取数据**：煤炉、雅虎闲置和闲鱼直接调网页端自己用的接口（煤炉和闲鱼都要求请求带签名，程序里自己实现了；闲鱼还要登录）；另外五个网站下载搜索结果网页，从中找出每件商品的标题、价格、图片和链接。
- **网站改版时**：原来的格式认不出了，程序会找出所有指向商品详情页的链接，从链接周围把信息捞出来，小改版一般扛得住。一件都认不出时，「关注」页会标出「解析到 0 件」，而且这一次不算数，免得修好后把一整页当成新货推出去。
- **防刷屏**：一次冒出大半页「新商品」，多半是网站换了排序，这一次只记下不推送。同一件商品被多个关注搜到，只推一次。
- **防被封**：同一个网站的请求之间留间隔，而且带随机；一个网站出错只记在状态和日志里，自己歇一会儿再试，不影响其他网站。
- **推送规则**：几秒内一起查到的合成一条推送。卖家删了重新上架的（标题、价格都一样），7 天内不再推。程序停了 6 小时以上再开时，这段时间冒出来的只推最新 5 件，其余的放在「上新」里。

它的局限：

- **有延迟**：它是轮询，实际延迟还包括平台收录、排队、网络和通知送达时间，不能用配置里的检查间隔作为最大延迟保证。
- **只看第一页**：比如煤炉是最新的 120 件。两轮之间新上架超过一页就会漏，热门关键词要写得具体一些。
- **要一直开着**：程序停了就不扫了。想 24 小时盯着，放到 NAS 或服务器上。

## 常见问题

- **「关注」页顶上说某些网站「连不上」**：多半是没走代理。煤炉、雅虎拍卖、乐天 Rakuma 在国内直连会超时，要走代理。程序默认跟着系统代理走，把 Clash 之类的「系统代理」打开就行，不用重启；程序在这台电脑上找到能用的代理时，提示旁边会有「用这个代理」，点一下就改成走它。已经在走代理还连不上，看看代理软件开着没有、节点能不能用。
- **「拦下了请求」**：等待冷却结束，在设置页查看剩余时间；持续发生时应降低查询频率并检查账号状态。换 IP 不能保证消除限制。
- **某个网站显示「解析到 0 件」**：多半是那个网站改版了。运行 `python -m goodsmare search 网站 关键词 --dump dump/`，把存下来的页面对照 `goodsmare/sources/` 下对应的解析代码修改，也欢迎提 Issue 或 PR。
- **推送里没有封面**：先看上面「推送渠道怎么选」里各渠道的显示方式。Server酱、PushPlus 要点开卡片才有图。
- **煤炉、雅虎闲置推了很多不相干的**：它们的搜索会匹配商品描述，填「标题必须包含」过滤。标题里有日文、英文两种写法的，写成 `フィッシュマンズ|fishmans`。最快的办法是在「上新」页点「选择」，把不相干的点选出来，再点「屏蔽」：这几件以后不再显示、不再推送；弹窗里会从标题拆出词来让你点选，加进排除词，标题里缺了关键词的，还会推荐把它设成「标题必须包含」。电脑上把鼠标移到卡片上，图片右下角的小圆钮能直接屏蔽单件。屏蔽错了，点提示条上的「撤销」，或者在「设置 → 其他」里恢复。
- **一次冒出一大堆「新商品」**：程序判断为网站换了排序，这一次只记下不推送，下一轮恢复正常。

## 开发

```bash
python -m unittest discover -s tests -t .
```

只用 Python 标准库（3.9+）。结构：

```
goodsmare/
  sources/     每个网站一个文件：search() 发请求，parse() 解析；闲鱼的扫码登录也在 xianyu.py
  monitor.py   扫描：每个网站一个线程轮着查；基线、过滤、降价、防刷屏、合并推送
  notify.py    各种推送渠道
  pages.py     推送页
  access.py    手机访问：局域网地址、手机用哪个地址
  qr.py        手机访问用的二维码
  migrate.py   从旧版迁移
  store.py     SQLite：见过的商品、推送记录、扫描状态、推送页
  web.py       本地网页的 HTTP 接口
  static/      网页
  es256.py     煤炉接口要的签名（纯 Python 实现的 P-256）
  htmlparse.py 一个够用的小 DOM 和选择器
```

解析器的测试用的是按各网站页面结构手写的样例，不是抓下来的真实页面。网站改版后，欢迎把新的页面结构补进 `tests/test_parsers.py`。
