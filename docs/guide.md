## 支持的网站

| 网站 | 怎么查 |
|---|---|
| 煤炉 Mercari（含 Mercari Shops、煤炉拍卖） | 网页端自己用的接口，按上架时间倒序 |
| 雅虎拍卖 Yahoo!オークション | 搜索页，新着順 |
| 雅虎闲置 Yahoo!フリマ（原 PayPayフリマ） | 网页端的 JSON 接口，不通时退回网页 |
| 乐天 Rakuma | 搜索页，按上架时间、只看在售 |
| 骏河屋 Suruga-ya | 搜索页，按更新时间、只看有货 |
| Mandarake | 通贩搜索页，按入荷顺、隐藏售罄 |

## 第一次使用

1. **新建关注**：一个关注就是一个搜索词。
   - 关键词用日文最准。表单里有常用谷子词对照，比如 吧唧 → 缶バッジ、立牌 → アクリルスタンド，点一下就填进去。
   - 勾选在哪几个网站找，填价格区间（日元）。
   - 煤炉和雅虎闲置的搜索会匹配商品描述，结果比较杂，建议填「标题必须包含」。同一个东西有几种写法的，用竖线隔开，有一个就行：`フィッシュマンズ|fishmans`。不想要的，比如「まとめ売り」，填进「标题不能包含」。
   - 全角半角、大小写会自动统一：`ｶﾝﾊﾞｯｼﾞ` 等于 `カンバッジ`。
2. **先预览**：点「先搜一下看看」，直接看搜出来的东西，灰掉的是会被你的条件过滤掉的。
3. **第一次扫描只记不推**：新关注第一次扫描只记下现有商品，之后新上架的才推送，不然一加就刷屏上百条。改了关键词或价格区间也会重新记一遍。
4. **配推送**：在「推送」里加一个渠道，点「发一条测试」。测试会用最近抓到的一件真实商品；还没抓到过的话，就用第一个关注现搜一件。所以测试消息里的封面和链接，和正式推送一样。

## 推送渠道怎么选

| 渠道 | 适合 | 要填 |
|---|---|---|
| Server酱 | 推到微信，最省事 | SendKey（[sct.ftqq.com](https://sct.ftqq.com)）。免费版每天 5 条，本程序每轮扫描只合成一条发 |
| PushPlus | 推到微信，免费额度更多 | Token（[pushplus.plus](https://www.pushplus.plus)） |
| 企业微信群机器人 | 企业微信里带封面的图文卡片，点开直达 | 群机器人的 Webhook 地址 |
| 钉钉 / 飞书群机器人 | 用钉钉、飞书的 | Webhook。钉钉的安全设置选「自定义关键词」就填 `goodsmare`，选「加签」就把密钥也填上 |
| Bark | iPhone，每件单独一条，点开直达商品页 | Bark App 里的设备 Key |
| ntfy | 安卓 / 自建 | 主题名 |
| Telegram | 用 TG 的 | Bot Token 和 Chat ID |
| 邮件 | 不急的 | SMTP 服务器和授权码（QQ、163 邮箱要用授权码，不是登录密码） |
| Webhook | 自己接 QQ 机器人等 | 地址。每轮把命中的商品以 JSON POST 过去 |

每件商品都带封面图和「打开商品页」链接，但各渠道能显示到什么程度不一样：

- **Server酱、PushPlus**：走的是微信的模板消息，微信聊天里那张卡片本身放不了图片，**点开卡片**才看得到封面和商品链接。
- **想在通知里直接看到图**：iPhone 用 Bark，或者用企业微信群机器人（图文卡片）。
- **飞书**：群机器人的消息放不了外链图片，只有文字和链接。

开着网页时，还可以在「推送」里打开浏览器通知和提示音。

## 命令行

```bash
python -m goodsmare                         # 启动（后台扫描 + 网页）
python -m goodsmare --port 8788             # 换端口
python -m goodsmare once                    # 只扫一轮就退出，适合定时任务
python -m goodsmare search 煤炉 初音ミク     # 试搜一个网站，看解析得对不对
python -m goodsmare search 骏河屋 初音ミク --dump dump/   # 顺便把原始页面存下来
python -m goodsmare add 初音ミク フィギュア --max 8000 --must フィギュア --exclude まとめ
python -m goodsmare list                    # 列出关注和每个网站的最近状态
python -m goodsmare rm <ID>
python -m goodsmare test-notify             # 给所有推送渠道发测试
```

网站名可以写中文：煤炉、雅虎、雅虎闲置、乐天、骏河屋、mandarake。

## 放在 NAS / 服务器上长期运行

```bash
python3 -m goodsmare --host 0.0.0.0 --no-browser
```

对局域网开放网页时**一定要设口令**：编辑 `data/config.json`，把 `web.token` 改成一串别人猜不到的字符，然后重启。之后用 `http://机器IP:8787/?token=你的口令` 打开一次即可，浏览器会记住。

也可以不开网页，只用 `once` 配合定时任务：

```cron
*/5 * * * * cd /path/to/goodsmare && python3 -m goodsmare once >> goodsmare.log 2>&1
```

## 设置说明

- **扫描间隔**：默认 180 秒，最少 30 秒。关注多、网站多时别设太小，容易被封 IP。
- **同站请求间隔**：同一个网站两次请求之间至少等几秒，默认 3 秒。不同网站并行扫描，互不拖慢。
- **代理**：某些网站连不上或返回拦截页时填，例如 Clash 的 `http://127.0.0.1:7890`。只支持 HTTP 代理，日本节点更稳。
- **汇率**：默认自动获取（每 12 小时一次），拿不到就用你填的值。

所有数据都在 `data` 文件夹里：

- `config.json`：设置、关注、推送渠道。网页里改和直接改文件都行，每一轮扫描都会重新读取，不用重启。
- `goodsmare.db`：SQLite 数据库，记着见过的商品、推送记录和各网站的扫描状态。

## 工作原理

```
你的关注（关键词 + 价格、必含词、排除词）
        ↓  每 3 分钟左右一轮
六个网站同时去搜，只看「按上架时间排序」的第一页
        ↓
把各站的结果整理成同一种格式：编号、标题、价格、封面、链接
        ↓
和数据库里「见过的」对比：没见过 = 上新；见过但比上次便宜 = 降价
        ↓
过滤：价格不对、缺必含词、有排除词、已售的都扔掉
        ↓
合成推送发出，同时显示在网页的「上新」里
```

- **怎么取数据**：煤炉和雅虎闲置直接调网页端自己用的接口（煤炉要求每个请求带一个签名，程序里自己实现了）；另外四个网站下载搜索结果网页，从中找出每件商品的标题、价格、图片和链接。
- **网站改版时**：原来的格式认不出了，程序会找出所有指向商品详情页的链接，从链接周围把信息捞出来，小改版一般扛得住。一件都认不出时，「关注」页会标出「解析到 0 件」，而且这一次不算数，免得修好后把一整页当成新货推出去。
- **防刷屏**：一次冒出大半页「新商品」，多半是网站换了排序，这一次只记下不推送。同一件商品被多个关注搜到，只推一次。
- **防被封**：同一个网站的请求之间留间隔，而且带随机；一个网站出错只记在状态和日志里，不影响其他网站。

它的局限：

- **有延迟**：它是隔一段时间去看一次，不是网站主动通知，最多晚一个扫描间隔。
- **只看第一页**：比如煤炉是最新的 120 件。两轮之间新上架超过一页就会漏，热门关键词要写得具体一些。
- **要一直开着**：程序停了就不扫了。想 24 小时盯着，放到 NAS 或服务器上。

## 常见问题

- **某个网站显示「连不上」或「拦下了请求」**：网络问题，或者被对方的人机验证拦了。等一会儿、调大间隔，或者在设置里配代理。
- **某个网站显示「解析到 0 件」**：多半是那个网站改版了。运行 `python -m goodsmare search 网站 关键词 --dump dump/`，把存下来的页面对照 `goodsmare/sources/` 下对应的解析代码修改，也欢迎提 Issue 或 PR。
- **推送里没有封面**：先看上面「推送渠道怎么选」里各渠道的显示方式。Server酱、PushPlus 要点开卡片才有图。
- **煤炉、雅虎闲置推了很多不相干的**：它们的搜索会匹配商品描述，填「标题必须包含」过滤。标题里有日文、英文两种写法的，写成 `フィッシュマンズ|fishmans`。
- **一次冒出一大堆「新商品」**：程序判断为网站换了排序，这一次只记下不推送，下一轮恢复正常。

## 开发

```bash
python -m unittest discover -s tests -t .
```

只用 Python 标准库（3.9+）。结构：

```
goodsmare/
  sources/     每个网站一个文件：search() 发请求，parse() 解析
  monitor.py   扫描循环：基线、过滤、降价、防刷屏
  notify.py    各种推送渠道
  store.py     SQLite：见过的商品、推送记录、扫描状态
  web.py       本地网页的 HTTP 接口
  static/      网页
  es256.py     煤炉接口要的签名（纯 Python 实现的 P-256）
  htmlparse.py 一个够用的小 DOM 和选择器
```

解析器的测试用的是按各网站页面结构手写的样例，不是抓下来的真实页面。网站改版后，欢迎把新的页面结构补进 `tests/test_parsers.py`。
